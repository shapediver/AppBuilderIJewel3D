# AppBuilder IJewel 3D

Instructions for every coding agent (Claude Code, Cursor, Codex, Copilot). Keep this file tool-neutral; tool-specific notes go in that tool's file (`CLAUDE.md` for Claude Code).

This is the **iJewel3D / WebGI host** of ShapeDiver App Builder (GitHub: [AppBuilderWebGI](https://github.com/shapediver/AppBuilderWebGI), local folder `AppBuilderIJewel3D`), a fork of [AppBuilderSdk](https://github.com/shapediver/AppBuilderSdk) that renders with Pixotronics **WebGI** (`webgi` package, host code in `src/webgi/`). The session still uses `@shapediver/viewer.session`. Host vs SDK details, where to change what, and the intentional feature gaps: `.agents/rules/ijewel-repo.md`. Don't spend a session rediscovering them.

## Repositories

- `upstream` remote → AppBuilderSdk. Merge SDK releases with the `merge-upstream` skill; keep host-specific code out of the shared submodule.
- Two git repos: the root (`AppBuilderWebGI`, usually on `development`) and `src/shared`, a separate clone of `AppBuilderShared` (same library as the SDK, often behind SDK `development`). Run shared git commands as `git -C src/shared ...`. The root commits only the shared pointer (`<KEY>: shared update`) plus host app, `tests/jest/` and `public/`, after `src/shared` is committed.
- `src/shared` is consumed by the SDK and other hosts: no `webgi` imports, no iJewel-only hacks, prefer additive APIs. Before changing it, read `src/shared/.cursor/rules/host-compat.mdc`.
- Path aliases: `@AppBuilderLib/...` and `@AppBuilderShared/...` → `src/shared/...`, `@webgi/...` → `src/webgi/...`, `~/...` → `src/...`. FSD layers under `src/shared`: `shared/`, `entities/`, `features/`, `widgets/`, `pages/`. Host code (`src/webgi/`, `src/AppBuilder*.tsx`) is not FSD.
- New worktree: `node scripts/agents/setup-worktree.mjs` copies the local files listed in `.worktreeinclude` from the main checkout, inits `src/shared`, runs `pnpm install` and writes `.vscode/settings.json`. Each agent tool runs it automatically (see "Agent config"); run it by hand if `src/shared` is empty. Check out `task/<KEY>` in both repos.

## Unused on this host

Do not add or assume these ShapeDiver viewer packages unless the product explicitly gains them:

- `@shapediver/viewer.viewport`
- `@shapediver/viewer.features.*` (drawing, interaction, transformation-tools, attribute-visualization)

They exist in shared source for other hosts. This app stubs DRAWING/INTERACTION UI and omits AR, anchors, attribute visualization and scene-tree widgets. Import shared modules via **concrete file paths**, never parameter/appbuilder barrels, so those packages are not pulled into the host bundle. **WebGI is used**: don't treat `webgi` as unused.

There is **no e2e** here: don't add Playwright. Jest in `src/shared` (mocks in `tests/jest/`) is the automated test surface. Shared rules mention Playwright, `tests/`, `.agents/rules/e2e-playwright.md` and the `e2e-testing` skill; those parts don't apply to this host.

## Line endings

The working tree is CRLF, git stores LF (`autocrlf`), and eslint enforces `linebreak-style: CRLF`. Edit with your tool's file edit tool. `sed -i` and plain Python writes produce LF and hundreds of lint errors, and Prettier (`endOfLine: auto`) does not repair them. In Python, write with `newline=''` and `\r\n`.

## Checks (changed files only)

- Format: `npx prettier --write <files>`.
- Lint: `npx eslint <files>`
- Typecheck: `npx tsc --noEmit -p .` at the root. The host `tsconfig` includes only `src/AppBuilderRoot.tsx` and its transitive imports, so unused shared modules that import `@shapediver/viewer.features.*` are not checked. IDE lints are no substitute.
- Unit test: `npx jest --config jest.config.mjs src/shared/<path>`. `jest.mock` replaces all exports: when you add a named export, keep the real ones with `...jest.requireActual(...)` in the suites that mock that module, and run them too (or `pnpm test`).
- Import Zod from `@AppBuilderLib/shared/lib/zod`, not `zod` / `zod/v4` (eslint restricted).
- After a batch: prettier, eslint, tsc, affected jest, then one targeted browser check if the UI changed.

## Browser

### Skills

Procedures. When a task matches, read the skill's `SKILL.md` and follow it (skip this if your tool already loaded it as a skill).

- `.agents/skills/browser-diagnosis/SKILL.md`: Reproduce and diagnose the iJewel/WebGI App Builder in a browser — dev server and slugs, WebGI query params, window.SDV (session only), counting PUT computations, finding who committed a value. Use when debugging UI or the viewport.
- `.agents/skills/custom-component/SKILL.md`: Create or change a React component that reads style props from the Mantine theme (useProps / usePropsAppBuilder, useCustomTheme.ts registration, @docAttached tags, pnpm run docs). Use when adding a component or changing its theme-controlled props.
- `.agents/skills/fsd-migrate/SKILL.md`: Move files into the Feature Sliced Design layers under src/shared (shared, entities, features, widgets, pages), updating every import. Shows a migration plan and waits for confirmation. Use when asked to migrate or move components, hooks or types between FSD layers.
- `.agents/skills/merge-upstream/SKILL.md`: Merge shapediver/AppBuilderSdk upstream/development into this repo, dropping SDK-only pieces (e2e, ShapeDiver viewport UI, extra entries) and keeping the WebGI host. Use when asked to sync, update or merge from upstream.
